# RViz 可视化桥接 —— 使用说明

## 这是干什么的

在**电脑的 RViz 里**实时看到板子相机拍到的：
- **点云**（按高度着色）
- **每个方块的 3D 位置**（立方体线框）
- **类别 + 置信度 + 夹角 + 点数 + RMS**（文字标签）
- **表面法向量**（红色箭头 —— 这个最能"看见夹角"）
- **坐标系**（X/Y/Z 三轴）

## 为什么不让板子跑 ROS

```
板子：Ubuntu 18.04  →  装不了 ROS 2 Humble（要求 22.04）
                     而且 Jetson Nano 跑 RViz 会卡死
电脑：Ubuntu 22.04  →  已经装好 ROS 2 Humble（/opt/ros/humble）
```

所以分工：**板子只发数据（TCP），电脑负责可视化**。

```
板子                                    电脑
run_realsense.py                        cloud_bridge.py          rviz2
  --ros 10.42.0.1:9100                    ↓                        ↓
  点云+检测结果  ──TCP 9100──→  /camera/points (PointCloud2)  → 点云
                                /detections    (MarkerArray)   → 框+标签+箭头
```

传输协议（自定义，为了不在板子上装 ROS）：
```
┌────────────┬──────────────┬────────────────┬──────────────┐
│ 'K4PC' 4B  │ 头长度 u32   │ 头 (JSON UTF-8) │ 点 float32   │
└────────────┴──────────────┴────────────────┴──────────────┘
```

## 怎么跑（三个终端）

### 终端 ①：电脑上启动 ROS 桥接

```bash
source /opt/ros/humble/setup.bash
/usr/bin/python3 ~/jetson-deploy/ros_bridge/cloud_bridge.py
```
看到 `TCP 监听 0.0.0.0:9100，等板子连进来…` 就成了。

（或者用一键命令：`b ros`）

### 终端 ②：电脑上打开 RViz

```bash
source /opt/ros/humble/setup.bash
rviz2 -d ~/jetson-deploy/ros_bridge/cloud.rviz
```

### 终端 ③：让板子发数据

```bash
b run 'cd ~/work/realsense && python3 run_realsense.py --print --ros 10.42.0.1:9100'
```

**注意 `10.42.0.1` 是电脑在直连网线上的 IP**（`enp5s0`）。你可以用 `b` 确认。

## RViz 里怎么操作

| 操作 | 鼠标 |
|---|---|
| 旋转视角 | 左键拖动 |
| 平移 | 中键拖动（或滚轮按下拖动） |
| 缩放 | 滚轮 |
| 对准某个点 | 点工具栏 **FocusCamera** 再点那个位置 |

**左侧 Displays 面板**可以勾选/取消：
- `PointCloud2` —— 点云。`Size (Pixels)` 调大能让点更明显
- `Detections` —— 框/标签/箭头
- `Grid` —— 地面网格（1 格 = 10cm）
- `TF` —— 坐标系

**视角默认**对准 `(0, 0, 1.0)`（相机前方 1 米），距离 1.8m —— 正合适看桌上的方块。

## 怎么判断数据对不对

| 现象 | 说明 |
|---|---|
| RViz 里什么都看不到 | ① 板子连上了吗（看终端①有没有"板子已连接"）② Fixed Frame 对不对（应该是 `camera_depth_optical_frame`）|
| 点云位置不对 | 板子的深度/内参有问题，先用 `run_realsense.py --print` 单独确认 |
| 有框没有点云 | 点云被 `--ros-max-points` 抽没了？默认 30000 点，够用 |
| 卡顿 | 调小 `--ros-hz`（默认 10Hz）或 `--ros-max-points`（默认 30000） |

**带宽估算**：30000 点 × 12 字节 = 360 KB/帧，10 Hz = **3.6 MB/s**。
千兆直连完全够（实际能到 100+ MB/s）。

## 参数

板子侧（`run_realsense.py`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--ros HOST:PORT` | 关 | 电脑的 IP 和端口 |
| `--ros-hz` | 10 | 每秒最多发几帧（RViz 不需要 30Hz） |
| `--ros-max-points` | 30000 | 抽稀到多少点再发 |

**为什么默认只发 30000 点**：RViz 渲染点数太多会卡；而且抽样对精度影响很小
（见 `lab3_angle.py` 第 ⑥ 节：280 点 → 0.24°，93 点 → 0.40°）。

## 这套架构的价值

**传感器和执行器分开、计算和可视化分开**，是机器人系统的标准做法：

```
板子（算力小、在现场、可能没显示器）  →  只负责采集和计算
电脑（算力大、有显示器）              →  负责可视化和调试
网络                                  →  用标准协议连起来
```

以后换相机、换算法、换显示工具，这条线都不用改。
这也是 ROS 存在的意义 —— 我们只是在这里用了个"轻量版"。
